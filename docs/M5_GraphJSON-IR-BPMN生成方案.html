Graph-JSON IR 与 BPMN 生成方案

把 Byteval 编辑态思想与"节点-边 graph-JSON IR → BPMN 生成"研究设想融合成一套可落地方法论
融合命题 · Thesis
用 graph-JSON 做图原生 IR（忠实 BPMN），但把"模型生成"约束在嵌套的 SESE 片段上：每次 function call 只吐一个结构完备的局部图。于是——澄清阶段先钉死网关语义 → 片段按结构化方式组合 → 结构化即 sound-by-construction，局部 validate 通过 ⟹ 全局 soundness 基本免费，只有 rigid（非结构化）片段才需重型验证。最后 render 成 BPMN 2.0（+DI）。编辑仍走 function call，建模为保不变式的图变换。

1 · 融合命题与设计原则

五条设计原则

继承 Byteval 新增贡献 补 Byteval 缺口
原则内容来源
P1 图原生 IR扁平 nodes[]/flows[]，关系与结构分离，容忍半成品继承
P2 语义左移网关语义在"生成前"由澄清钉死，生成期只消费不猜测新增
P3 结构化优先function call 粒度 = SESE 片段；rigid 仅兜底新增
P4 机器算候选scope 用连通性∩类型算合法集，语义决策交给 Agent继承
P5 视图分离layout 剥离为平行表 → 渲染成 BPMN-DI继承

2 · Byteval 思想 × 研究设想：逐条映射

研究设想（五步）Byteval 可借鉴思想融合后的升级
① 先需求澄清，控制网关无歧义 ASCII Brief：用户确认拓扑，Agent 管绑定；只在多候选/语义不确定时才问 Brief 升级为网关消歧协议，产出结构化 Intent Spec，把 XOR/OR/AND、default、join 类型、循环边界在建图前钉死
② function call + 生成局部图 plan-apply 批量子图；add-* 增量原语；scope = 连通性∩类型 function-call 粒度上抬到 BPMN 模式片段（SESE）；scope 复用为数据引用候选收敛
③ 伴随 validate，局部+全局无问题 validate 吃 IR、容忍半成品、一次收集、两级严重度；deps=edges∪bindings 两层 validate：片段 soundness + 组合 soundness；补 Byteval 缺的反向可达
④ 转成 BPMN IR→DSL render 六步；layout 剥离；type::uuid ID 生成 render：graph-JSON → BPMN 2.0 XML；layout → BPMN-DI；readable-id → element id
⑤ 编辑也走 function call remove-node 级联清理；bind 同端口覆盖幂等；session 读写分离 编辑 = 图变换规则（前置/后置条件），保不变式 + 增量校验

3 · graph-JSON IR 结构设计

继承 Byteval IR 的四条编辑友好特征（扁平 / 关系与结构分离 / 字段最小 / 容忍半成品），但对 BPMN 做一处关键分叉：控制流与数据流分开存。

// graph-JSON IR 顶层结构
{
  "meta":  { "name":"贷款审批", "notation":"bpmn", "source":"" },
  "nodes": [
    { "id":"start_0", "type":"event",   "subtype":"start" },
    { "id":"task_1",  "type":"task",    "subtype":"service", "name":"信用评估" },
    { "id":"gw_1",    "type":"gateway", "subtype":"exclusive", "default":"flow_3" }
  ],
  "flows":     [ // 控制流 = sequenceFlow（网关只作用于它）
    { "id":"flow_2", "source":"gw_1", "target":"task_2", "condition":"amount > 1e6" } ],
  "data":      [ { "id":"do_1", "type":"dataObject", "name":"Application" } ],
  "dataAssoc": [ { "source":"task_1", "target":"do_1", "direction":"out" } ],
  "layout":    { "task_1":{ "x":300, "y":0 } },  // 视图分离 → BPMN-DI
  "fragments": [ { "id":"f_xor1", "kind":"bond", "entry":"gw_1", "exit":"gw_1j" } ] // RPST 骨架
}

关键分叉：控制流 ⊥ 数据流（表示分开，分析合并）

Byteval（执行引擎）：deps = edges ∪ ref-bindings   —— 合并
  理由：运行时"引用了谁就必须等谁先跑完"，数据引用天然是控制依赖。

BPMN（建模记法）  ：sequenceFlow ⊥ dataAssociation  —— 分开
  理由：网关的分支/汇聚语义只作用于控制流；数据关联不参与 token 流动。

融合裁决：
  表示层  flows 与 dataAssoc 分开存 → 忠于 BPMN 语义
  分析层  需要"上游可见性"时，临时算  vis = 传递闭包(flows ∪ dataAssoc)
          —— 这正是 scope 候选计算所需，复用 Byteval 的 ∪ 思想

两条贯穿线

② validate 无处不在但分两层：③局部即时、④全局缝合、⑥增量。早失败早退回。

5 · SESE / RPST：连接 block 与 graph 的桥

定义 5.1 · SESE 片段
片段 F 是 SESE（Single-Entry-Single-Exit），当且仅当存在唯一入边 ein 与唯一出边 eout，使 F 与图其余部分仅通过这两条边相连。直觉：一个能被单入单出封装、可整体当抽象节点替换的子流程。
定义 5.2 · RPST（Refined Process Structure Tree）
把工作流图唯一地、O(n) 线性时间分解为嵌套 SESE 片段的树，每片段属四类之一：
类型含义结构化?
trivial单条边（原子）✓
polygon顺序：子片段串行首尾相连✓
bond网关配对：split + join，中间多条并列分支（XOR/AND/OR 的结构化形态）✓
rigid不可约：跨分支同步、任意跳转、共享汇聚等非结构化拓扑✗ 需重型验证
为什么它是桥：
graph 表示 ：graph-JSON 忠实保留图结构（回边 / 共享汇聚 / 事件），不退化成树。
block 分析 ：RPST 把图看成"嵌套块"，于是同时获得三种能力——
             生成：每次 fc 只填一个 SESE 占位（块状、LLM 友好 → 命中"块状易生成"）
             验证：soundness 沿 RPST 自底向上组合
             复用：片段 = 可 clone 的模式（借 Byteval clone-ref）
定理 5.4 · sound-by-construction
若工作流图 G 是"结构化"的（RPST 不含 rigid 片段，且每个 bond 的 split/join 同类型配对），则在自由选择网语义下，G 的 soundness 由构造保证，无需展开状态空间。
证明（归纳）：trivial/polygon 平凡 sound；配对 bond sound（split 产生的 token 恰被同类型 join 消费）；sound 片段的嵌套组合仍 sound（SESE 边界保证 token 不泄漏）。
推论 5.5 · 验证负担坍缩
只有 rigid（非结构化）片段才需重型 soundness 检查。策略：引导模型只用结构化片段（emit_* 自带配对 join）→ 绝大多数图 sound-by-construction；仅当必须非结构化才落 rigid，并对该片段单独跑有界状态空间探索。

Soundness 形式化（van der Aalst）→ BPMN 映射

(S1) option to complete   ≈ 无死锁（每个 token 都能推进）        → global_gateway_balance
(S2) proper completion    ≈ 每活动能反向到达 end event          → proper_completion  ★ Byteval 缺
(S3) no dead transitions  ≈ 无不可达活动（Byteval 已有正向可达） → no_dead_activity

6 · 逐阶段深入

阶段① · 澄清 → 网关消歧（仅五类结构歧义才问）

Q1 分支互斥性  多条件可同真时，XOR（择一，需优先级）/ OR（择多）/ 还是本就 AND（恒并行）?
Q2 默认路径    XOR/OR 若无条件命中走哪? —— 缺 default ⟹ 潜在死锁（违反 S1）
Q3 汇聚语义    并行分支要同步（AND-join）还是简单合并（XOR-join）? —— split/join 错配是经典 bug
Q4 循环边界    回边起止、退出条件、while/until、最大迭代
Q5 隐式并行    "做 A、B、C" 是顺序还是并行?

产物是焊进 Intent Spec 的网关语义表，让阶段③的片段发射器消费确定语义而非猜测（P2 语义左移）。职责边界同 Byteval：用户确认业务拓扑，Agent 管技术绑定。

阶段③ · function-call 两层 API

Tier-1 片段发射器（结构完备 by construction）—— 主力
  emit_sequence(entry, steps[], exit)
  emit_exclusive(split_props, branches[{cond, body}], default, join)   // 自带配对 XOR-join
  emit_parallel(branches[{body}], join)                                // 自带 AND-join
  emit_inclusive(...) / emit_loop(body, exit_cond, kind) / emit_event_based(...)
     每个 emit_* 只吐一个 SESE 片段 → 立即局部 validate → 通过才纳入组合

Tier-2 图原语（细粒度，供编辑/修复）—— 对应 Byteval add-node/add-edge/bind
  add_node / add_flow / set_condition / set_default / bind_data / remove_* / replace_gateway_type
  scope(node, port)         // 借 Byteval：连通性∩类型 → 数据引用候选，把猜变选
  validate(scope=frag|all)  // 借 Byteval：两层

阶段③+④ · 两层 validate 检查项清单

层检查项级别说明 / 来源
局部
（片段级）		frag_is_seseerror片段恰好单入单出
gateway_balancederrorbond 内 split/join 同类型配对
xor_or_defaulterrorXOR/OR split 有 default 或条件可证穷尽（防死锁）
cond_expr_presenterror每条 XOR/OR 出边有 conditionExpression（default 除外）
data_ref_in_scopeerror数据引用可在 scope（vis 闭包）内解析
全局
（组合级）		start_unique / end_existserror恰好 1 start / ≥1 end 借 Byteval
forward_reachablewarning从 start 正向可达 已实现
proper_completionerror每节点反向到达 end event（= S2）补缺口
global_gateway_balanceerrorRPST 校验结构化；rigid 单独跑 soundness（= S1）

cross_boundary_referror跨 pool/lane/subProcess 引用合规 借 cross_scope

阶段⑤ · render（graph-JSON → BPMN 2.0，六步）

1. ID 生成    readable(task_1) → BPMN id（Activity_x）；维护 idMap   [借 render 步骤1]
2. 节点展开   node.type/subtype → task / gateway / event 元素
3. 边转换     flow{source,target,condition} → <sequenceFlow> + <conditionExpression>
4. 数据关联   data/dataAssoc → <dataObject> + <dataInput/OutputAssociation>
5. 网关配对   Intent Spec join 语义 → 配对 join 元素 + gatewayDirection
6. 布局分离   layout → <bpmndi:BPMNDiagram>（DI）；纯 API 路径可不填 → 自动布局  [借改④]

7 · 相对 Byteval 的三个明确增量

增量Byteval 现状本方案
① 语义左移建好后 validate 网关生成前澄清钉死网关语义，模型消费而非猜测
② sound-by-construction逐条静态检查SESE/RPST 让结构化图 soundness 由构造保证，负担坍缩到 rigid
③ 补反向可达checkReachability 只有正向 BFS（已知缺口）补 proper_completion（从 end 反向 BFS），对齐 S2

反过来三个直接继承：graph-JSON 的扁平/关系分离/容忍半成品（IR 哲学）、scope 的连通性∩类型（把猜变选）、layout 平行分离（→ BPMN-DI）。

8 · 贯穿微例子：贷款审批

NL："金额超100万走人工复核，否则自动放款"

① 澄清：Q1 互斥?→是(XOR)；Q2 默认?→自动放款；Q3 汇聚?→两分支都到"放款完成"(XOR-join)
        Intent Spec: gw_1=exclusive, default=自动放款, join=exclusive@gw_1j
② 骨架：polygon[ start, 信用评估, bond_xor(gw_1 .. gw_1j), end ]
③ fc  ：emit_sequence(start → 信用评估 → gw_1)
        emit_exclusive(gw_1, [{amount>1e6→人工复核},{else→自动放款,default}], join=gw_1j)
        → 局部 validate：frag_is_sese ✓  gateway_balanced ✓  xor_or_default ✓
④ 缝合：全局 validate → proper_completion ✓（两分支都反向可达 end）  no_dead_activity ✓
⑤ render：<exclusiveGateway default="Flow_else"> + <conditionExpression>amount &gt; 1000000</>
⑥ 编辑："再加金额>500万走董事会" → replace 单条件 bond 为 emit_exclusive 三分支
        → 增量重验 bond_xor 片段即可，全局不动。

9 · 关键取舍（答辩 / 写作用）

张力选择理由
block vs graphgraph 表示 + block（SESE/RPST）分析忠实图论 + 块状生成/验证模块性
控制流 / 数据流表示分开，分析合并忠于 BPMN 语义 + 复用 Byteval ∪ 做 scope
网关语义澄清期锁定，生成期消费soundness 左移；模型不猜网关
生成粒度SESE 片段优先，rigid 兜底结构化 ⟹ sound-by-construction
何时问用户仅五类结构歧义借"别过度打扰"，给精确触发条件
验证时机局部即时 + 全局缝合 + 增量容忍半成品 + 早失败早退回
编辑对象只编辑 graph-JSON，BPMN 只读产物对齐 Byteval "改 IR，不改 DSL"

10 · 落地优先级与风险

P0 骨架：graph-JSON schema + RPST 分解 + 局部/全局 validate（先打通 soundness 闭环）
P1 生成：Tier-1 片段发射器（emit_*）+ 澄清网关消歧协议
P2 渲染：graph-JSON → BPMN 2.0（+DI）；BPMN schema / 语义校验
P3 编辑：Tier-2 图变换 + 增量校验；scope 数据绑定收敛
风险缓解
rigid 片段 soundness 验证是唯一重型环节（状态空间可能爆炸）有界探索 / 自由选择网化简 / 尽量引导结构化避免 rigid
澄清过度会打断体验严守"仅五类结构歧义"触发条件
OR-join（inclusive）语义 non-local、易错MVP 先禁 OR-join，只 XOR/AND（结构化）
数据流 soundness 常被忽略纳入全局 validate，别只查控制流
LLM 生成 rigid 片段结构不稳定function call schema 强约束；生成后立即局部 validate，不过即退回

11 · 一句话总结

本方案用 graph-JSON 做图原生 IR（忠实 BPMN），把 Byteval 的"改 IR / render 出产物、scope 把猜变选、validate 容忍半成品、layout 分离"直接继承；再叠加三个增量——网关语义在澄清期左移锁定、用 SESE/RPST 让结构化图 sound-by-construction、补上 Byteval 缺的反向可达（proper completion）。生成走 function call 逐片段吐局部 SESE 图并即时局部 validate，缝合后跑全局 soundness，最后 render 成 BPMN 2.0（layout→DI）；编辑同样走 function call，建模为保不变式的图变换 + 增量重验。
