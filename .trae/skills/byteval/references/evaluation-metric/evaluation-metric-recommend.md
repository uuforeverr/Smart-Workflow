## 适用范围

当用户已经有评测对象或业务任务，但还缺少“评测维度 / 评分标准 / rubric / 指标体系”时，使用本页。

典型触发：

- “帮我推荐一套评测标准”
- “这个摘要任务应该从哪些维度评估”
- “我想做评估器，但还没有评分规则”
- “给这个业务场景生成评测维度”

本页只负责推荐评测标准，不直接生成评估器 skill。若用户已经给出标准并希望创建评估器，转到 `references/evaluator/evaluator-generate.md`。

## 能力来源

本流程融合自现有 `standard-recommend` skill：

- 先判断用户信息是否足够
- 信息不足时补问，不调用接口
- 信息足够后把需求提炼成明确 `--prompt`
- 调用标准推荐脚本生成 Markdown 结果
- 成功后原样展示脚本输出或读取生成文件给用户

当前能力已内置到 `byteval evaluation-metric recommend`。执行时优先使用 CLI 命令，不再依赖外部 `standard-recommend` skill 目录。

## 信息充分性检查

执行前必须先确认用户需求至少覆盖这些信息：

- 评测对象 / 任务类型：如小说摘要、新闻摘要、机器翻译、角色扮演、多轮对话、推荐理由、图文理解
- 评测目标：如通用质量评估、推荐场景、审核场景、风格控制、短摘要压缩、安全合规
- 特殊约束：如篇幅要求、是否控剧透、目标受众、输出格式、业务侧重点、是否多模态

如果缺关键项，先问 1 到 3 个简洁问题。问题只围绕生成 `--prompt` 所需的信息，不要先执行脚本再补问。

## 执行步骤

1. 判断用户是否已有明确标准：
   - 已有标准：不走推荐，转到 `references/evaluator/evaluator-generate.md`
   - 没有标准但需求充分：进入标准推荐
   - 需求不充分：先补问
2. 将用户需求提炼为一个具体 prompt。
   - prompt 要包含任务类型、评测目标、约束和业务侧重点
   - 不要只写“推荐评测标准”这类空泛描述
3. 生成一个可读标题作为 `--title`。
   - 建议形如 `<场景名>-评测标准.md`
   - 标题只用于输出文件命名，不承载完整需求
4. 调用标准推荐脚本。
5. 成功后原样展示脚本返回；如果用户需要标准正文，再读取脚本保存的 Markdown 文件并摘要或完整展示。

## CLI 执行协议

优先执行项目内 CLI：

```bash
byteval evaluation-metric recommend \
  --prompt "<提炼后的用户需求>" \
  --title "<文件标题>" \
  --output-dir /tmp \
  --timeout 300
```

执行配置：

- 建议 timeout 至少 300 秒
- 默认真实接口：`https://byteqa.bytedance.net/eval_agent/openapi/dimension_generate`
- 可通过 `--endpoint` 显式覆盖接口地址
- 全局 `--json` 或命令级 `--format json` 会返回结构化结果

示例：

```bash
byteval evaluation-metric recommend \
  --prompt "小说摘要任务，目标是评估摘要忠实度、完整性、可读性，并要求控制剧透" \
  --title "小说摘要评测标准" \
  --output-dir /tmp \
  --timeout 300
```

## 输出处理

CLI 输出约定：

- text 成功：`evaluation_metric_file=<path>`
- json 成功：`{"file_path":"<path>"}`
- 网络异常 / 服务异常：命令返回非 0，并输出具体错误

处理建议：

- 成功时把文件路径告诉用户，并按需读取文件内容
- 网络异常或服务异常时，原样转述错误，不要改写成“已推荐”
- 若输出文件路径存在但内容为空，按失败处理并提示用户重试
- 不要二次加工成另一套标准，除非用户明确要求“帮我整理措辞”，且要说明整理自脚本输出

## 衔接评估器创建

推荐出的标准通常是评估器创建的前置输入。

后续路径：

1. 用户确认推荐标准可用
2. 将标准正文整理为结构化 JSON，或让用户把标准保存为可访问文档链接
3. 转到 `references/evaluator/evaluator-generate.md`
4. 使用：
   - `--eval-standard '<json>'`，适合标准已在当前上下文
   - `--eval-standard-url <url>`，适合标准已沉淀到飞书文档等链接

建议结构化 JSON 形态：

```json
{
  "忠实度": {
    "评估要点": ["是否严格遵循原文", "是否存在事实虚构"],
    "评分规则": {
      "5分": "完全忠实，无事实错误",
      "3分": "有轻微细节偏差但不影响理解",
      "1分": "存在明显事实错误或核心遗漏"
    }
  }
}
```

## 注意事项

- 信息不足时先补问，不要调用脚本撞运气
- 不要自行虚构评测标准来冒充 CLI 结果
- 不要输出“我将为你推荐”这类空承诺；能执行就执行，不能执行就说明缺什么
- 标准推荐结果不是最终评估器，创建评估器还需要场景名、标准来源和输出目录等参数
- 若用户要的是 Byteval 平台资源创建，而不是本地 evaluator skill bundle，应先说明当前能力生成的是本地 skill，再确认是否继续接入平台应用或工作流
